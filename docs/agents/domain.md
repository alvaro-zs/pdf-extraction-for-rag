# Domain docs

This repository uses a single context: a root glossary and repository-wide architecture decision records (ADRs).

## Before exploring

Read [the root glossary](../../GLOSSARY.md), when present, and relevant decisions under [docs/adr/](../adr/).

If these documents do not exist, proceed silently. Create them lazily through the domain-modeling skill when terminology or architectural decisions are actually resolved.

## Vocabulary

Use the glossary's terms in issue titles, proposals, hypotheses, and test names. For a missing concept, first check whether an existing term fits; record a real vocabulary gap for domain modeling.

## Decisions

If a proposal contradicts an existing ADR, name and link that ADR and explain why the decision should be revisited.
